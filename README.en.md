## Getting started

Requirements: [Node.js](https://nodejs.org) 20.12 or higher.

**1. Download the project and install the dependencies**

```bash
git clone https://github.com/pietrogimenes/discord-bot-components-v2.git
cd discord-bot-components-v2
npm install
```

**2. Create the `.env` file**

```bash
cp .env.example .env
```

On Windows (PowerShell), use `copy .env.example .env`.

**3. Create the bot and fill in the token**

1. Go to the [Discord Developer Portal](https://discord.com/developers/applications) and create an application.
2. Under **Bot**, click **Reset Token** and paste the token into `BOT_TOKEN` in the `.env`.
3. Under **OAuth2 > URL Generator**, select the `bot` and `applications.commands` scopes, choose the permissions below and use the generated link to invite the bot.

Recommended permissions: View Channels, Send Messages, Send Polls, Add Reactions, Manage Messages, Manage Channels, Manage Roles, Manage Server (AutoMod), Kick Members, Ban Members and Moderate Members.

**4. Run it**

```bash
npm run dev
```

> To test faster, put your server ID in `GUILD_ID`: the commands show up instantly.
> The bot's role must be **above** the roles it manages (autorole, role panel and moderation).

It works? Now you can [keep the bot online 24/7](#hosting-keep-your-bot-online-247): on HyzeCloud you can try **7 days for free**.

## Environment variables

Only `BOT_TOKEN` is required. Each optional variable enables a feature.

| Variable | Description |
| --- | --- |
| `BOT_TOKEN` | Bot token (required) |
| `GUILD_ID` | Registers the commands instantly in this server |
| `MOD_LOG_CHANNEL_ID` | Moderation log, AutoMod alerts and closed tickets |
| `EVENT_LOG_CHANNEL_ID` | Event log: deleted and edited messages, members joining and leaving |
| `LOG_MESSAGE_CONTENT` | `true` shows the message text in the logs (requires the *Message Content Intent*) |
| `WELCOME_CHANNEL_ID` | Channel for welcome messages |
| `AUTOROLE_ROLE_ID` | Role given to every new member |
| `SUGGESTIONS_CHANNEL_ID` | Channel for `/suggest` suggestions (default: the channel where it was used) |
| `TICKETS_CATEGORY_ID` | Category where tickets are created |
| `TICKETS_STAFF_ROLE_ID` | Staff role that can see and close tickets (recommended) |
| `WEBHOOK_LOGS_URL` | Webhook that receives error logs |

To get an ID in Discord, enable **Developer Mode** (Settings > Advanced), right-click the channel, role or server and choose **Copy ID**.

### Privileged intents

The bot only requests the intents it needs. With no optional variable, it works with just the token.

| Intent | When it is requested | Where to enable |
| --- | --- | --- |
| Server Members | `WELCOME_CHANNEL_ID`, `AUTOROLE_ROLE_ID` or `EVENT_LOG_CHANNEL_ID` | Developer Portal > Bot > Privileged Gateway Intents |
| Message Content | `EVENT_LOG_CHANNEL_ID` with `LOG_MESSAGE_CONTENT=true` | Developer Portal > Bot > Privileged Gateway Intents |

## Commands

**General**

| Command | Description |
| --- | --- |
| `/help` | Help center with a category menu |
| `/ping` | API and WebSocket latency |
| `/avatar` | A user's avatar, with download links |
| `/userinfo` | A user's information (also in the **User info** context menu) |
| `/serverinfo` | Server information |
| `/botinfo` | Bot statistics |
| `/poll` | Native Discord poll |
| `/suggest` | Suggestion modal with category and anonymous option |

**Moderation** (each command requires the matching Discord permission)

| Command | Description |
| --- | --- |
| `/ban`, `/unban` | Ban and unban (`/unban` searches the ban list) |
| `/kick` | Kick |
| `/timeout`, `/untimeout` | Mute for a time (`30s`, `10m`, `2h`, `1d`, `1w`, up to 28 days) |
| `/warn add\|list\|remove\|clear` | Warning system |
| `/purge` | Bulk delete messages, with an optional user filter |
| `/slowmode` | Channel slowmode |
| `/lock`, `/unlock` | Lock and unlock a channel |
| `/automod spam\|mentions\|words\|presets\|status` | Turns native AutoMod rules on and off (the rules keep working while the bot is offline) |

**Server**

| Command | Description |
| --- | --- |
| `/role add\|remove` | Gives or removes a role from a member |
| `/rolepanel` | Panel with buttons so members can pick roles (up to 5 per panel) |
| `/ticket panel` | Sends the support panel. The member opens a ticket through a modal and the bot creates a private channel |
| `/ticket close` | Closes the ticket (there is also a button inside the ticket) |
| `/announce` | Sends an announcement in Components V2 |

Moderation commands check the role hierarchy, notify the user by DM when possible and log the action in the `MOD_LOG_CHANNEL_ID` channel.
The role panel does not accept roles with administrative permissions.

## Data

- Warnings are stored in `data/warns.json` (ignored by git). For larger bots, replace `src/functions/warns.ts` with a database.
- Tickets do not use a database: the owner is saved in the channel topic.

## Creating a command

Create a file in `src/discord/commands/` (everything there is loaded automatically):

```ts
import { createCommand } from "#base";
import { notice } from "#functions";
import { ApplicationCommandType } from "discord.js";

createCommand({
    name: "hello",
    description: "Says hello 👋",
    type: ApplicationCommandType.ChatInput,
    async run(interaction) {
        await interaction.reply(notice("success", `Hello, ${interaction.user}!`));
    }
});
```

See [CONTRIBUTING.md](CONTRIBUTING.md) for the project conventions (Components V2, modular subcommands, responders). It is written in Portuguese.

## Common problems

**The commands do not show up in the server**
Check that you invited the bot with the `applications.commands` scope. Global commands can take a while to appear; with `GUILD_ID` filled in they show up instantly. Restart the Discord app (Ctrl + R) if they still do not appear.

**`Used disallowed intents`**
An optional variable requires a privileged intent that is not enabled. Enable it in *Developer Portal > Bot > Privileged Gateway Intents* or remove the variable. See the intents table above.

**The bot cannot moderate a member or give a role**
The bot's role must be **above** the target role or member in the server's role list, and it needs the matching permission.

**"Algo deu errado" (something went wrong) when submitting a modal**
Check the responder type: a modal opened by a **command** uses `ResponderType.Modal`; a modal opened by a **button** uses `ResponderType.ModalComponent`.

**The ticket is not created**
The bot needs the **Manage Channels** permission. If you use `TICKETS_CATEGORY_ID`, check that the ID belongs to a category.
